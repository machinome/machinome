# Running domain-error command retirement, 23 September 2026

Framework base: clean primary `main` at `42e5b92c6d18fc0281aac305342d4f62c7cfc1a9` (running source unchanged since `a9f10b89`). This is a maintainer conformance finding from the public endpoint-domain diagnostic alongside the independent viewer's `refuse-nonfinite-running-law-start` cycle, not a claim that the Curta presently authors this law.

Read-only public `Sim` probe used an `AssemblyNode` declaring `Time.running()`, `feed = Driver(default=0)`, a revolute coordinate, and `feed.drives(shaft.turn, law=lambda ...: lambda feed: machinome.math.sqrt(0.1-feed))`. `Sim(..., dt=0.1, meshes=False, record=8)` constructed with state `{feed: 0, shaft.turn: 0.31622776601683794}`. Immediate `sim.move('feed', to=0.2)` raised `ValueError: math domain error`. Afterwards `sim.tick == 0`, state and trajectory were unchanged, but `sim.commands` contained the `feed` command in status `active`. The input remained owned by a command whose request could not complete.

The same model with `feed=Driver(default=0.2)` failed during its rest render with `ValueError: math domain error`; it cannot publish a version-5 document with that authored start. The viewer's accepted invalid-start document remains a viewer-side diagnostic, not a producer fixture.

A second read-only public probe used `feed=Driver(default=1)` and a running `feed*feed` law driving the same coordinate. `Sim` started at `{feed: 1, shaft.turn: 1}`. Immediate `sim.move('feed', to=1e308)` returned `completed` at tick 0 and banked `{feed: 1e308, shaft.turn: inf}`, also writing that bank to its trajectory. The source input was finite; the law's numeric result overflowed to infinity. This is the same law-result seam as the domain failure, but no exception currently reaches `Run.integrate`.

Source seam: `machinome/simulation/program.py::_evaluated` calls the compiled graph's numeric `evaluate` for running laws, allowing the domain `ValueError` out or returning infinity. `machinome/simulation/run.py::Run.integrate` stages bank and records, then catches `RunConflict`, `TooManyCrossings`, `UnsupportedLaw`, `StopInvariantError`, and `LandingInvariantError` to retire moved commands. A raw `ValueError` misses that typed refusal path; a returned infinity is never challenged. The existing simulation spec's “A continuous law is integrated over a tick and increments propagate” requires a failed tick to leave bank/tick/tree standing and retire moved commands `refused`; ADR-105 makes command ownership explicit, ADR-106 defines the one-law two-readings evaluation, and ADR-111 governs producer-generated corpus parity.

No repository source was changed by this baseline probe. At that point the frozen corpus did not cover this domain-error case and no cross-runtime parity claim could be made; the paired completion gate below supersedes that historical limitation.
