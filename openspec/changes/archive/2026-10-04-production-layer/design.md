## Context

The originating model is Curta-Type-I-3x's manifest entry `simulation.mechanistic:MechanisticCurta`, not its unimplemented 2x sibling. It creates and omits source children during structural rendering, includes rigid subfeatures that are not independently handled pieces, and carries flexible leaves outside the printed inventory. Its current clearing-loop mounting is explicitly simulation-only; whole-machine geometry acceptance remains open. The author BOM supplies acquisition and finishing evidence, not a certification of this simulation as fabrication geometry.

This proposal adds a bundled layer without making production an ancestor of model or simulation imports. ADR-087, ADR-166, ADR-084/085, topmost rigid boundaries, flexible-leaf and sheet contracts constrain it. The cycle identity and exceptional base are recorded in proposal.md.

## Goals / Non-Goals

Goals: independently bind production assets to existing model instances; delegate actual children; preserve exact occurrence counts and hierarchy; report partial/invalid ownership; retain maker instructions and mass basis; supply coherent portable draft outputs.

Non-goals: model migration, a new intrinsic-requirement declaration, an alternative Curta model, CAM/slicing, stock nesting, invented geometry, simulation mass/support integration, supplier search, CLI discovery, a viewer protocol change or fabrication certification. Single repeated-member selectors and profile inheritance/replacement are deferred: reject production subclasses of a concrete production profile in this first implementation, so inherited ownership cannot become accidental.

## Decisions

### Public modules and values

All imports name their defining module; neither `machinome` nor `machinome.production` reexports these names. Public value records are immutable and compare by their complete declared fields:

- `machinome.production.profile`: `Production[Model]`; constructor takes one existing compatible node instance, or a model reference when declared inside another Production. Only declared child bindings are descriptors; arbitrary field names never drive dispatch.
- `machinome.production.item`: `Item(target, process, *, mass=None)`. Class-body Item becomes a bound immutable item on instance access. Targets are existing class child/path/repeat references, a `Reference` below, a nonempty tuple of those references for named siblings, or the bound model class itself to select the root. Duplicate selected occurrences are rejected. No copies of quantity in the profile.
- `machinome.production.process`: `Printed(material=None)`, `Cut(stock)`, `Sourced(requirement, *, offer=None)`. Unspecified printed material remains explicit unknown; the Curta sheet does not justify inventing PLA. Printed/Cut settings such as infill remain maker instructions, not universally typed machine operations. Sourced requirement is a Standard or Product.
- `machinome.production.material`: `Material(name, *, density_kg_m3=None)`; nonempty name, finite strictly positive optional density.
- `machinome.production.stock`: `Sheet(material, *, thickness_mm)`, positive finite thickness. `stock` reports finished cut-part count and selected sheet specification, with purchased-sheet quantity explicitly unknown. Rod procurement and allocation are prose until another evidenced contract is ratified.
- Neutral `machinome.components`: `Standard(name, *, designation, grade=None)`, `Product(manufacturer, part_number, *, conforms_to=())`. These lightweight catalogue records import no production or node module. This cycle does not add an intrinsic requirement declaration to model classes. It compares only an explicit existing requirement available through the facade; no model rewrite is prerequisite.
- `machinome.production.sourcing`: `Offer(product, supplier, sku, *, url=None)`. Offer names one Product; for Standard sourcing its product must explicitly list the same Standard in conforms_to, and for Product sourcing it must match that Product. This is catalogue assertion, not verification of certification.
- `machinome.production.instruction`: `Step(*subjects, instructions=Markdown(path))`, `Markdown(path)`. Subjects must be Item or child-production declarations of that same profile. Text paths are captured against the source file that declared the Step, not the importing parent. Literal inline prose and arbitrary attachment trees are deferred.
- `machinome.production.mass`: `MeasuredMass(grams, *, evidence)`, `SolidMass()`, with finite nonnegative measured grams and mandatory local evidence file. Unknown is expressed by omitted mass, not zero.
- `machinome.production.results`: immutable `BomLine`, `StockLine`, `ResolvedStep`, `MassBasis`, `MassSummary`, `Finding`, `ExportResult` records. `MassSummary` has `known_grams`, `complete`, `unknown_occurrences`, and `basis: tuple[MassBasis, ...]`. Each MassBasis declares `occurrence_path`, `grams`, `basis`, `reason`, and `evidence_path`; unknown grams and absent evidence are None. `Finding` has stable `code`, `severity`, `occurrences`, `declarations`, `message`, and `check_status`. Ordered results are tuples.
- `machinome.production.errors`: `DeclarationError`, `BindingError`, `ProductionConflictError`, `ProductionInputChangedError`, `ProductionExportError`.

Explicit unit suffixes keep production numbers separate from parameter declarations; a universal unit algebra would exceed the first consumer's need. Standard/Product are neutral because models may eventually state requirements without importing production; this cycle does not invent that declaration language.

The existing vet universe trusts framework imports except explicitly effectful entry points. Extend that existing classification to deny `machinome.model.ModelSnapshot` and `machinome.production.profile` in a pure model closure, because they observe files and can write artifacts. Pure `Reference`, component identities and recipe values remain available. Production assets are outside the model's import closure; this does not make production a prerequisite for model validation or change the existing purity policy.

The minimal public Python result contract is:

- Bound Item: `target_paths: tuple[str, ...]`, `process`, `mass_basis` (declaration or None), and `declaration_path: str` (root-relative production field path).
- BomLine: `line_id: str`, `status: str` (`assigned`, `unassigned`, `invalid`, `absent-target`), `process` (valid complete typed recipe or None), `requested_process` (declared rejected recipe or None), `quantity: int`, `occurrence_paths: tuple[str, ...]`, `declaration_paths: tuple[str, ...]`, `source_paths: tuple[Path, ...]`, `finding_codes: tuple[str, ...]`, `geometry_id: str | None` (None for sourced/unassigned/invalid/absent targets), `material: Material | None`, `requirement: Standard | Product | None`, `offer: Offer | None`. `process` is the complete validated typed recipe, not its display label; invalid recipes cannot enter assigned manufacturing groups.
- StockLine: `stock: Sheet`, `finished_count: int`, `purchased_quantity: int | None`, `occurrence_paths: tuple[str, ...]`; None means not allocated, never zero.
- ResolvedStep: `step_id: str`, `scope_path: str`, `subject_paths: tuple[str, ...]`, `instruction_path: Path`, `instruction_text: str`, `instruction_sha256: str`. Subject paths name model occurrences/assembled child boundaries; step IDs combine scope with declaration attribute.
- Occurrence: `path: str`, `parent_path: str | None`, `kind: str`, `model_type: type`, `parameters: Mapping[str, float | int | bool]` (immutable), `source_paths: tuple[Path, ...]`, `sheet_thickness_mm: float | None`, and `nominal_dxf: bool`. The sheet facts expose declared compatibility without building geometry. Selection returns tuples of these records. Actual-node membership is internal; no mutable node is handed out through result records.
- GeometryFacts: `content_id: str` (full canonical identity), `size_mm: tuple[float, float, float] | None`, `volume_mm3: float | None`, `watertight: bool`, `artifact_kind: str`, `artifact_sha256: str`. Canonical identity answers geometric grouping; byte digest identifies the actual artifact copied. Artifact facts do not pretend invalid geometry has a volume.
- ExportResult: `path: Path`, `coverage_complete: bool`, `findings: tuple[Finding, ...]`, `executed_code_provenance: str`. All exported bundles remain draft even when coverage_complete is true.

Root `bom`, `stock`, `steps` and `findings` are tuples of the respective records. `mass` is MassSummary. A child binding exposes the same contracts with root-relative occurrence paths; `parameters` is its actual occurrence's read-only parameter mapping. Paths use the facade's linked model names with `/` separators; the root is `.`. Declaration paths likewise use `/` separators, with repetition indices retaining model identity. Read-only mapping members cannot be mutated to alter cached results.

The BOM tuple carries incomplete coverage visibly: each unassigned candidate has its own `status="unassigned"`, `process=None`, `geometry_id=None`, quantity-one line with occurrence/source paths and `finding_codes=("unassigned",)`. These lines are never grouped by class, parameter or guessed geometry and need no artifact reading. An unsupported declared recipe produces `status="invalid"` per selected occurrence, no usable process/geometry identity, its original recipe in requested_process and stable finding codes; it never masquerades as a manufactured deliverable. An absent named target has a quantity-zero `status="absent-target"` diagnostic line, no occurrence/geometry, and its declaring path/source/finding code. Thus a caller reading only bom sees the gaps rather than needing to remember findings. No error is converted into a fabricated assigned line; ambiguous overlap still refuses bom. CSV adds status and finding_codes so draft gaps survive the human view, and artifact export copies only assigned valid lines.

### Narrow public model-reading boundary

`machinome.model` defines `Reference(model_type, path)`, `ModelSnapshot`, `Occurrence`, `GeometryFacts`, and `ModelInputChangedError`. `path` is a tuple of public attribute names. Reference permits constructor/build-created children such as the real Curta without changing its source into declarations. Existing declared references remain supported through the same adapter. Lists/tuples and repeat references expand in model order; every path segment uses actual bound attributes and a matched active tree occurrence, not class spelling. Missing/omitted targets yield an `absent-target` finding; foreign owners are binding errors. No wildcard strings, copied count, newly constructed default child, or arbitrary Python predicate.

`ModelSnapshot(model)` captures the supplied instance and establishes active topology only when occurrence facts are first needed; the caller does not call evaluate or supply a second plan. Its principal consumption methods are `occurrences`, `select(reference, *, scope=None)`, `geometry(occurrence)` and `copy_artifact(occurrence, kind, destination)`. Scope is an Occurrence from this same snapshot; selection cannot escape its subtree through an alias. Child production bindings retain this shared snapshot and actual occurrence, not a reconstructed node.

The facade also explicitly supplies the supporting facts needed to avoid private production imports: module functions `is_reference(target) -> bool` and `reference_path(model_type, target) -> tuple[str, ...]` recognize and validate supported references without constructing a model; snapshot methods `empty_selection(reference, *, scope=None) -> bool` and `selection_is_many(reference, *, scope=None) -> bool` distinguish an actual empty repetition from an omitted/missing named target and preserve tuple-shaped child bindings at zero or one occurrence. `validate()` checks the shared generation; `observe_input(path) -> str` pins a consumer source/evidence digest; read-only `input_hashes` and `executed_code_provenance` expose that generation's evidence. These are consumption/validation operations, not a new author-required lifecycle or mutable-node escape. This implementation clarification is within the delegated design: the original four-method sketch could not express repetition shape, sheet compatibility or shared profile/input checks without private access.

Structure-only reading adapts the existing core-owned `AssemblyNode._rest_children` path (original rest render and linking, without simulation), adding normal result validation and rigid-internal traversal where needed. It must preserve current motion/state/driver bindings and refuse an unsupported stateful legacy render rather than run simulation or invent driver defaults. No structural read calls `_prepare`, `assemble`, materialize, geometry adapters or marking hooks. Lifecycle links/cache population are permitted bookkeeping; source, parameters, active membership, operations and public running state retain their semantics. Failure cleanup is limited to framework-owned placement/rest bookkeeping and preserves held container identities; it must not copy and restore arbitrary user dictionaries or claim general user-code rollback. Instrumented fresh/advanced-state fixtures must establish this boundary before implementation is accepted. The geometry/copy methods use the existing native lifecycle only for the required artifacts and retain source-currency and pinned-read guarantees. Production imports this public facade only, never `core`, `_prepare`, raw private declaration resolution or artifact internals. Internal facade implementation may adapt existing structure reading, child linking, qualified resolution and piece facts, with narrowly reviewed source edits; there is no prerequisite redesign of the node lifecycle.

Occurrence records retain unique root-relative path, parent path, actual node identity, kind (`assembly`, `rigid-piece`, `rigid-feature`, `flexible-piece`), resolved parameters and reference membership. Topmost rigid nodes and flexible leaves are candidate obligations, not a claim that every terminal patch is a separately handled physical part. Descendants inside a rigid solid are features, not separate BOM obligations. Assemblies retain hierarchy but contribute no item unless explicitly sourced as a whole. Markings and Frames contribute none. Curta's RetainingSpring assembly is one author-BOM spring represented by five geometric patches: the initial partial profile must leave it unresolved, with explicit project reconciliation evidence, and cannot claim whole-machine completeness based on terminal coverage. No automatic grouping/fusion/exclusion hides that mismatch.

Do not expose a speculative `IntrinsicRequirement` type: if baseline has no requirement object, requirement facts are empty. Stock checks consume declared sheet thickness and the established nominal-DXF capability, not the existence of an already-built file; lazy export ensures its required DXF through the existing artifact lifecycle. Cut applied to a non-sheet or arbitrary assembly yields `unsupported-cut-target`. Printed applied to a flexible leaf yields `unsupported-print-target`; Sourced supports rigid/flexible pieces and whole assemblies. Flexible measured/sourced BOM entries need no deformation snapshot. Flexible SolidMass remains unknown with a finding; generating new rigid snapshots for it is excluded.

### Ownership and lazy access

Constructing a binding checks its declared model type and freezes profile records, without geometry work. The first occurrence-dependent access creates one shared ModelSnapshot for root and all children. Child production bindings receive the actual existing selected child instance with its current resolved parameters. A repeated child binding expands to independently bound children; instance access returns a tuple for repetitions, a bound Production for a single child. Parent `Step` referencing that declaration expands to all bound children.

Every physical obligation has at most one owner. An Item on a physical piece owns it; Sourced on an assembly owns its entire descendant physical set and is one purchased occurrence. Delegation reserves that subtree to its child even when the child leaves gaps. Parent selections inside it conflict. Overlap findings identify every competing declaration deterministically; declaration order never picks a winner. `findings` can inspect conflicts; `bom`, `stock`, `mass`, `steps` and `export` raise ProductionConflictError for overlapping ownership to avoid ambiguous totals. Missing coverage is nonfatal and appears in findings and outputs. Empty active repetitions contribute zero; an omitted named target is an explicit finding, not an invented instance.

`bom` resolves coverage and the geometry identities needed for manufactured lines; a manufactured BOM can therefore build geometry, while a sourced-only BOM needs none. `stock` resolves coverage and Cut compatibility. `steps` resolves subjects and instruction files, without mesh decoding. `mass` resolves coverage and explicitly requested volume. `findings` performs structural/recipe compatibility checks but does not force unrequested manufactured-identity or SolidMass geometry. Findings carry check status so an unrequested geometry-dependent check is not advertised as passed. `export` requests all bundle facts. No public evaluate method, plan, refresh or reset. The Curta slice verifies 15 active flexible carry wires structurally; they remain unassigned with made-wire instruction evidence because this cycle has no bent-wire process and must not call them purchased finished springs.

### Consolidation and mass

Sourced grouping key is the complete requirement plus chosen offer, never mesh, color or STEP provenance. Manufactured grouping key includes full canonical geometry content identity, complete process/stock/material value, mass declaration, and ordered instruction-content fingerprints of every Step that directly names that Item. A Step with several Item subjects influences all of them conservatively; no prose or subject-count inference decides its role. A Step naming only child productions remains an assembled-boundary instruction and does not alter internal recipes. Steps never manufacture another part. Thus differing finishing instructions or material never silently combine; equal artifacts with equal recipes combine across child boundaries while retaining every occurrence. Flexible sourced identity uses requirement, not shape at a simulated instant. Curta nuts use Standard("DIN 934", designation="M4x0.7"), evidenced by the author's BOM link to Bolt Depot product 4784 and that supplier's dimensional-standard statement; grade and manufacturer stay unspecified. Standard names denote actual evidenced standards, not arbitrary project requirement text.

Unknown geometry never substitutes a class/parameter identity. Artifact failure propagates as a contextual input error. MeasuredMass is per selected occurrence and evidence is retained. SolidMass uses only valid watertight positive finite volume in mm³ times density_kg_m3 / 1_000_000 to obtain grams, under a homogeneous-solid assumption. Missing density, invalid volume or flexible geometry stays unknown with basis/reason. Printed infill is not a multiplier. Summary known_grams is a partial subtotal when complete is false; total is never falsely represented as zero for unknowns.

MassSummary covers the full candidate set within the queried production subtree, including all unassigned/invalid candidates as unknown_occurrences. A valid sourced whole assembly collapses its covered descendant candidates to that one owner's mass basis, avoiding double weight; delegation contributes children exactly once. An absent declared target also marks complete false and retains its finding despite having no physical occurrence to weigh. Item assignment alone does not shrink the mass denominator to only assigned records.

### Coherent generation and export

Each binding freezes one model/profile generation. Direct construction such as `model = MechanisticCurta(); production = CurtaProduction(model)` is supported without a special loader or user lifecycle. Binding captures current model/profile source observations and marks `executed_code_provenance: unverified-direct-binding`; those observations cannot prove the bytes imported earlier. A model already belonging to the established sealed loader retains its verified executed-code provenance and checks. Both forms strongly observe current source contributors, profile closure and instruction/evidence files (canonical target, device/inode/size/mtime_ns/ctime_ns plus consumed content digests). Inputs are checked before and after each lazy operation. Changed source/profile/instruction invalidates the binding with ProductionInputChangedError; caller reloads code and constructs a new asset. No automatic reimport/reconstruction. Repeated calls reuse immutable facts only under that generation. Once an artifact identity has been consumed, replacement invalidates the entire root/child binding rather than mixing old BOM/mass with newly copied bytes; create a new binding to consume its new coherent pinned snapshot. A race on first consumption is retried or refused. Parent and held child outputs use the same invalidation boundary.

`export(destination)` creates a new portable directory; it refuses an existing nonempty destination. Build into an adjacent temporary directory and publish atomically after validation; a failure leaves no partial target. ExportResult holds path and completeness status. `production.json` declares `format: machinome-production`, `version: 1`, model/profile identities, resolved parameters, input hashes, nested bindings, occurrence owners, consolidated BOM and stock, steps, mass and findings/check status. `bom.csv` has line_id, status, process, description, quantity, occurrence_paths, finding_codes; `stock.csv` distinguishes finished_count from purchased_quantity (empty for unknown). JSON is authoritative; CSV fields use deterministic JSON encoding for lists.

`instructions.md` presents depth-first child instructions followed by parent's declared Steps, preserving explicit scope, subject paths, and declaration order at each level; it embeds copied Markdown text and links copied evidence. Version 1 Markdown/evidence accepts plain Markdown text, external http/https links and same-document fragment links only. Relative/absolute local links or images (including reference-style links), raw HTML image/link sources, file/data URLs and any unresolved dependency are refused contextually at steps/export; v1 does not silently copy arbitrary attachment trees or embed broken paths. The declaring Markdown/evidence file itself must resolve within its declaring source directory (or a descendant), with canonical resolution rejecting traversal or symlink escape. Referenced input files are never overwritten. Files sit under `files/<sha256>/<basename>` to retain separate same-filename child files without collision, and the manifest maps each declaration to its copied file. Only these explicitly referenced files are copied. Printed lines copy their pinned STL and Cut lines their nominal DXF under `artifacts/<artifact-sha256>.<extension>`; bought geometry and flexible snapshots are not fabrication deliverables. Content digests/identities in the manifest describe the same bytes copied. This is a maker bundle, never slicer-ready G-code or kerf compensation. Export is always labeled draft; completeness means declared coverage/check status only, not fabrication readiness. Curta's partial profile includes its simulation-only mounting/open acceptance limitation in a project-owned Step Markdown file and missing/reconciliation findings.

### Concrete Curta caller

The following proposed spelling uses the real root and named descendants without constructing a default CrankAssembly. `simulation.standard.layers` is the confirmed defining module for CrankAssembly; `AttachedCrank` remains the actual bound replacement subclass.

```python
from machinome.model import Reference
from machinome.production.profile import Production
from machinome.production.item import Item
from machinome.production.process import Printed
from machinome.production.instruction import Step, Markdown
from simulation.mechanistic import MechanisticCurta
from simulation.standard.layers import CrankAssembly

class CrankProduction(Production[CrankAssembly]):
    pin = Item(Reference(CrankAssembly, ("crank_handle_pin",)), Printed())
    pin_screw = Item(
        Reference(CrankAssembly, ("crank_handle_1", "crank_handle_pin_screw")),
        Printed(),
    )
    finish = Step(pin_screw, instructions=Markdown("file-and-thread-pin.md"))

class CurtaProduction(Production[MechanisticCurta]):
    crank = CrankProduction(Reference(MechanisticCurta, ("main_drive", "crank")))
    limitations = Step(crank, instructions=Markdown("draft-limitations.md"))

model = MechanisticCurta()
production = CurtaProduction(model)
assert production.crank.pin.target_paths == ("main_drive/crank/crank_handle_pin",)
draft_findings = production.findings   # structural; no geometry preparation
lines = production.crank.bom           # requests the selected manufactured artifacts
```

This two-source-part example deliberately leaves fitted main crank/grip, nuts and made wire unassigned; the delivered project profile adds the ratified four-unit draft slice and sourced nuts with their provenance. Files resolve beside the module declaring each Step; if profiles split into modules, each retains its own instruction directory. No example asserts whole-machine readiness.

## Risks / Trade-offs

- Raw STEP tree differs from finished author BOM → validate only an independently reconciled physical slice; record source-feature/finished-piece disagreements and unsupported geometry rather than replace it.
- Native preparation can be expensive and some dependencies conditional → construction stays cheap; minimal imports/install remain independent; each output states which facts it requested.
- Source loaded outside sealed loader cannot prove original executed bytes retrospectively → support direct binding with explicit unverified executed-code provenance and verified observations from binding onward.
- Cut proof is representative rather than current project end-to-end → retain Cut and validate `tests/sheet_project/frame_panel.py`, the existing 6mm laser-cut printer frame representative fixture linked to ADR-053's metamaquina-rebuild finding. The current Metamaquina2 ScadPart is not a SheetLeafNode and supplies no nominal DXF; no live project migration or end-to-end production claim is implied.

## Migration Plan

Add the public facade and bundled production modules through red-first framework tests. An independent implementation agent delivers real project-owned `production/` assets and `production/test_production.py` in a dedicated Curta3x repository worktree, with its own records and commits, binding the unchanged `simulation.mechanistic:MechanisticCurta` model. Framework fixtures cannot discharge this real consumer acceptance. Record both tested framework and project content commits, independent repository boundaries and narrow existing simulation regression evidence; no Curta model migration. No old API changes or database migration. Framework public manual work follows write-the-manual; the studio public API skill update is separately owned and committed under machinome-studio's contract, never added to the framework tree. They describe draft status and released/unreleased facts accurately. Rollback before integration removes the new modules/assets in their owning repositories; there is no global registry to repair.
