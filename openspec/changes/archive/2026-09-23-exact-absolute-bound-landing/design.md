## Context

The accepted simulation contract says an absolute move lands exactly and a move landing on an inclusive range bound completes. Curta's browser-preparation oracle (`reverser-asymmetric-browser-da9808a-02.json`) instead reports its final direct withdrawal `blocked`: after standing at `-4.942499999999999`, `move(to=3.9075)` computes native travel `8.85`, and ordinary `start + travel` is `3.9075000000000006`. A tiny public Driver → Prismatic fixture on framework main `8d0fd15` reproduces this with both literal high `3.9075` and a standing-read `Bound`; the direct joint is later snapped to the high bound, but the input remains above the requested endpoint. The viewer independently reproduces the same arithmetic and t=1 false stop on its own current main.

The framework's run currently models every request only as a delta. `Command` builds a timed `RampProgram(value, value + native, ticks)` and zero-duration integration seeds a delta; `Run.integrate` constructs committed values with `value + delta` before `_reached`. `Motion` already distinguishes a path's endpoint from its line delta and the run already has absolute landing staging for retained relations. The fix must use that principle for an absolute request without changing what relative travel or an interior sample means.

## Goals / Non-Goals

**Goals:** Preserve the converted native `to` endpoint bit and carry it through terminal propagation, inclusive-bound evaluation, commit, and active-command restore. Keep a real beyond-bound stop, intermediate path, first-error order, stop attribution and atomic refusal unchanged. Verify the originating Curta sequence and the separate viewer's equivalent behavior.

**Non-Goals:** No epsilon or near-contact waiver; no post-hoc status relabel, generic clamping, changed `by`/rate behavior, new solver search, CAD geometry change, public motion primitive or exported document-version bump.

## Decisions

1. **An absolute target is data, not a reconstructed sum.** `Run.move(to=...)` converts the target to native units once, keeps the existing native travel and legacy `RampProgram(value, value + native, ticks)` for requested/admitted reporting and *identical interior tick arithmetic*, and also retains the absolute native target on the command. An instantaneous move retains it likewise. A `by` command has no endpoint override. Conversion and source-order errors stay where they already occur. Internal snapshot state carries a pending `to` endpoint separately from the existing command record, with a default-empty legacy form; restore validates its native numeric type and finiteness **before** retiring any active command, and does not reconstruct a new-format endpoint from `bank - admitted + native` (which can lose the same bit). The existing public program identity and serialized machine document do not change.

2. **Terminal endpoint is integrated before stop detection.** Only a full terminal admission for a `to` command whose additive endpoint is not bit-identical to its target activates an exact endpoint path. Its ordinary delta continues to describe travel over `0 <= t < 1`; the tick-local source `Motion` retains the original line delta but has `at(1)` and its absolute landing set to the native target. `Run._pass` already owns an ordered `landings` map and `Propagation` already owns per-key motions: seed the source there and make the guarded endpoint branch of each reached determiner consume its sources' `Motion.at(1)` before `_reached`, rather than first producing all descendants from `values + deltas`. Direct wiring/formula/continuous-law output must retain its committed offset and history: where its old output is bit-identical to the relation's evaluated start, use its evaluated end as the absolute landing; otherwise retain its existing `old + increment` semantics using the exact endpoint source. Jump/self-read/Play/Follow paths must use their own actual integrated walk/landing, never a fresh static pose. The terminal map changes no t<1 sample or relation visitation order. A genuine stop at `t < 1` takes the existing partial segment and never commits the requested target. A later stop on another branch likewise remains a stop; this design does not suppress event search. The no-correction hot path remains byte-for-byte unchanged.

3. **No additive repair or final relabel.** Adjusting the delta by one ULP is not generally valid: a representable delta may not exist whose addition reaches an arbitrary float target. Snapping just the input after `_reached` would leave its driven joint and stop record inconsistent; changing only `blocked` to `completed` would preserve the wrong bank. Recomputing a retained/history-dependent graph from a static final pose would erase its path. The endpoint override therefore belongs to the tick-local motion/landing path, with the original edge order and search arithmetic. If implementation finds an unsupported relation shape that cannot honor the exact endpoint without changing its path, return to planning with a red fixture; do not add a silent approximation or runtime waiver.

4. **Paired runtime, separate repository.** The viewer has the same defect, so its owning change shall mirror the observable endpoint and snapshot behavior with shared minimal fixtures and the actual Curta command sequence. The producer change does not edit viewer source. Existing version-13 profile data and numeric Bound expressions are unchanged; this is runtime conformance, not a wire feature.

## Risks / Trade-offs

- **An exact terminal endpoint can change a discontinuous branch at t=1.** Evaluate the authored graph at that endpoint in its existing order; test one-sided discontinuities and true earlier crossings. No tolerance or branch merge is allowed.
- **A descendant can be history-dependent.** Reuse its actual integrated path and absolute landing mechanism; never substitute static `Program.values_of` for a retained relation. Test Play/Follow/self-read, or return to planning if that cannot be preserved.
- **Snapshot shape can change for active absolute commands.** Add optional internal target state without altering existing command tuples or the serialized machine program; validate it before restore mutation, accept default-empty legacy snapshots without inventing a missing target, and test old/current handling, malformed type/nonfinite values, reset, restore and two independent runs.
- **Additional endpoint work could slow ordinary ticks.** Guard on a terminal `to` with a bit-different additive endpoint; measure the Curta oracle and unchanged hot-path focused suite before accepting.

## Migration Plan

No project or document migration. The framework and viewer runtime changes are paired for production use, with separate OpenSpec cycles; an old viewer continues to exhibit the old outcome until its own change integrates. Preserve the isolated worktree and roll back by reverting the two framework cycle commits if final validation rejects the design; never alter Curta geometry to mask the issue.

## Open Questions

The apply phase must prove that the existing path evaluator can propagate a source's exact terminal `at(1)` through every edge kind exercised by the originating run while retaining its interior samples. A failed proof is a design conflict to return for review, not permission to narrow the accepted command contract silently.
