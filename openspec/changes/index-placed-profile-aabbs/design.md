## Context

`profile_overlap` currently prepares both complete placed profiles before scanning their polygon pairs in authored left-then-right order, rejecting pairs with strict AABB separation before SAT. ADR-144 permits only successful complete placements and pair decisions to live in a private 256-placement/1,024-pair cache for one integration attempt. The Curta Type I reverser trial in the proposal supplies a concrete repeated case: the frozen version-13 document's 18-degree/0.1-second tick has 1,560 numeric contacts, 780 distinct pair keys, 136 distinct placements, and 45,445,536 pair-AABB checks; no SAT projection is needed because its pairs are separated. Baseline CPU10 pinned runs took 8.395/8.644 seconds for the tick and 1.570/1.521 seconds in `profile_overlap`.

A process-local 2D bounding-box-tree prototype, not a repository edit, reduced the same tick to 7.246/7.187 CPU seconds and `profile_overlap` to 0.322/0.616 CPU seconds, with the same ordered-contact digest `46cdac2bff6972f1cf4f3b9ba2a2ac1204c3a306212cbb0fac2cc9eb31582cd4` and 214-key bank-bit digest `3e44081383251e2e2c12b91a58f03336ff887a465e840b8a26d88788d686983d`. Its 510,624 tree-node tests replaced the 45.4 million ordinary pair-box tests. The pinned input and oracle hashes are in the proposal; the process-local probes are `/tmp/curta_installed_perf_probe.py` and `/tmp/curta_bvh_probe.py`. The prototype eagerly attached a tree before predicate success; that violates the success-only cache contract and **must not** be copied into production.

The earlier prototype's two-tree/+37.6 kB figure selected the later post-tick reverser cache, not the crank cache, and is superseded rather than acceptance evidence. On the actual 136-placement crank cache, the baseline retained placement graph is 14,691,688 bytes and the final candidate is 16,305,965 (+1,614,277), counting tuple-subclass `__dict__` and trees; 130 trees remain. Paired `tracemalloc` full-run peaks are 234,301,384 and 235,962,453 (+1,661,069). The largest single tree is about 32,380 bytes; the live tree graph at build reached about 2,011,748 standalone deep bytes. Counts remain bounded by the existing 256-placement integration cache, with no universal byte cap; authored polygon counts remain unbounded.

## Goals / Non-Goals

**Goals:** Reduce the repeated, strictly separated Curta-sized numeric contact cost while preserving every existing predicate and integration-cache observable. Keep extra retained data within the existing cache values and their attempt lifetime. Prove both semantic parity and a material paired CPU improvement on the frozen producer trial.

**Non-Goals:** New public API or profile format; changed SAT arithmetic, epsilon, sampling, Bound admission, installed-cover proof, viewer optimization, or a global/profile-object index. The current revised Curta covers are not claimed to be adopted by this change.

## Decisions

1. **Only index an eligible reused placement inside the existing cache.** When the right placement was already successfully cached, both current placements have been completely validated, and the problem is large enough, build a private 2D AABB tree over the right placement's authored polygon boxes. Otherwise use the existing nested scan. There is no second registry or cross-attempt lifetime. Direct/no-cache and uncertain-key calls take the ordinary path; they create no persistent index. A box on the right is useful because each left polygon can query it while the right placement is reused across many sample positions.

2. **Use a conservative workload gate, not a public input limit.** The eligible gate is at least 32 left polygons, at least 16 right polygons and at least 512 possible polygon pairs, plus right-placement cache reuse. CPU10 cold/direct microprobes found the eager tree 16–31% slower at 8-by-8, 8-by-16, 16-by-16 and 32-by-32, whereas 591-by-159 was about 41–44% faster; 591-by-19 was neutral cold but about 11% faster with a warm right placement. Warm 32-by-32 was about 26% faster, warm 64-by-16 about 8% faster, while warm 128-by-8 regressed about 6%. Skew probes found 1-by-4,096 and 2-by-4,096 eager cold tree calls took 35.3/34.1 ms versus 18.0/14.9 ms for the ordinary evaluator; at 1-by-16,384 and 2-by-16,384 they took 188.5/176.7 ms versus 72.2/72.1 ms. Although many later calls could amortize that cost, a second use does not promise them. Requiring at least 32 left queries excludes those cases, while retaining the measured warm 32-by-32 benefit and the pinned 591-by-19/159 Curta work. These counts are a private heuristic, never a refusal or a polygon cap; the final transactional implementation must remeasure them and return for review if evidence contradicts the design.

3. **Preserve first-error and first-contact order.** The existing `_placed` work runs in full for left, then right, before a tree query. A tree node's box is only a conservative union of its child boxes. Queries use the same strict `<` separation tests; building and querying use comparisons/min/max only, with no midpoint, span or arithmetic that could overflow formerly legal finite inputs. Any survivor indices are sorted into original right-polygon order before the existing exact pair AABB and SAT code; left polygons retain their original order. Tree construction can reorder its private nodes, but not predicate visitation. Signed-zero ties in the tree can affect only private traversal, never the ordered transform, projection or numeric result.

4. **Publish the tree transactionally.** If the cached right placement has no tree, construct it into a local candidate and query that local value. Only after the *entire* predicate returns successfully may the implementation attach it to the cached placed value alongside the existing pending-placement and pair publication. If placement, tree construction, or SAT raises, the previously cached placement remains unchanged; no failed or partially prepared index is reusable. An uncached right placement can follow the ordinary path on its first use. Eviction of the placed value evicts its tree; integration-context exit discards both. The existing uncertain-key guard bypasses the entire cache, including any index.

Alternatives rejected for this cycle: a sorted-X sweep still tested 34.1 million boxes and increased the pinned tick to 9.208 CPU seconds; an eager 64-pair tree regresses small cold calls; a separate tree registry complicates the bounded lifetime and failure transaction; a process-global or immutable-profile index cannot represent placed boxes and would cross integration attempts. Viewer code requires its own measured benefit and change record; its pinned old-document baseline is 1.641 CPU seconds for the tick, but no viewer index candidate has been proved.

## Risks / Trade-offs

- **Extra tree memory and build churn** → Keep trees attached only to placed values inside the 256-entry attempt cache and leave first-use/small calls ordinary. The pinned trial's measured +1.61 MB retained placement graph and +1.66 MB traced peak are accepted for this cycle; do not add speculative compacting or a separate registry.
- **Hidden error or changed SAT priority** → Red-first tests with late contact, a later collapsed edge, an earlier overflowing SAT projection, signed zeros and extreme finite placements; compare exact result/error order against the ordinary evaluator.
- **A tree-box arithmetic or pruning mistake** → Build unions by comparisons of validated finite boxes, use strict disjointness, sort survivors, and compare ordered-contact plus all 214 bank bits in the frozen Curta tick.
- **Microbenchmark threshold overfits** → Require paired CPU10 runs under identical pinned input, source revision and cache configuration; abandon or revise the private gate if the final transactional implementation lacks material end-to-end benefit. No public behavior depends on the gate.

## Migration Plan

No migration. Existing profile data, document version, public signatures and viewer contract remain unchanged. The isolated cycle can be dropped before integration if correctness or material performance evidence fails.

## Open Questions

No public design choice remains open. The measured memory and private-gate crossover apply to the frozen old-trial document, not the project's unadopted revised covers or a universal workload; further use needs its own empirical check.
