## Why

The source-backed OperatingCurta takes minutes for a few seconds of ordinary motion. A bounded profile on framework `5d5ba18` attributed 39.2 of 77 profiled seconds to 287,529 `declared_ports` calls; child declaration lookup repeatedly re-enters the same class traversal. The Curta performance working record independently measured this cost and a memo prototype.

## What Changes

- Reuse each completed class's declared-port map while returning a fresh mapping to callers.
- Preserve inheritance, site-joint specialization, duck-typed coordinates, and class lifetime semantics.
- Demonstrate the improvement on a bounded real Curta operation while retaining its numerical, source-timing, carry, and stop contracts.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `joints`: repeated port enumeration retains the same declaration results and caller-owned mappings, including specialized child classes.

## Impact

`machinome/motion/ports.py`, `machinome/node/declarative.py` (class completion marker), declaration tests, and the Curta running caller. No public API, document format, search tolerance, or event law changes. This standalone worktree branches from framework `main` at `c81a585`. The pilot explicitly approved a clean isolated worktree while preserving primary checkout's untracked `docs/examples/v8-engine/`; worktree setup was manual because `scripts/dev-env` correctly refused that pre-existing dirty primary checkout. No primary file was moved, hidden, or edited.
