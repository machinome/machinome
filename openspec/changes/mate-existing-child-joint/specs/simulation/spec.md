## MODIFIED Requirements

### Requirement: Mate mechanical contracts retain existing execution and publication

Running and clocked compilation SHALL resolve moving mate Bound reads, ranges and additive constraints to the existing child joint and SHALL bank no second coordinate for the mate's assembly port. For a fresh-freedom mate, the mate wiring SHALL remain the existing identity
edge into that joint. A reused-joint mate SHALL add no wiring edge and SHALL
retain its original qualified joint id, guarded rest defaults, retained value
and self-targeted law behavior. Untimed enumeration, running and clocked Bounds SHALL retain their existing scope-specific expression validation, supported expression limits, contact search, outward admission, committed own-coordinate semantics, atomic refusal and replay rules. Explicit mate control selections SHALL use the selected child joint's existing placement and publish the existing control fields, including operation_span where explicit selection requires it. No document field or version SHALL be added. A model using none of the new mate contract forms SHALL retain its existing caller behavior and document bytes.

#### Scenario: A running mate uses one physical bank coordinate

- **WHEN** a running crank mate reads another moving mate in its Bound and has an added constraint plus an explicit control
- **THEN** the bank contains each generated joint exactly once, its constraint reads use those joint ids, and its control selects the same joint id without an assembly-port bank alias

#### Scenario: Running contact retains existing admission and replay

- **WHEN** a Curta-shaped mated crank request meets the pawl-dependent stop, then a later request relieves it
- **THEN** blocked travel, release and snapshot replay match the corresponding ordinary-joint fixture under existing tolerances and atomicity

#### Scenario: Clocked and untimed constraints keep their rules

- **WHEN** a supported clocked request or untimed binding uses a Bound or added constraint through a moving mate
- **THEN** it is checked against the generated joint using the existing solver or enumeration semantics and existing unsupported cases remain refused

#### Scenario: Existing documents stay unchanged

- **WHEN** existing non-mate fixtures and existing simple-mate fixtures are exported without the new contract forms
- **THEN** their documents are byte-identical to the baseline and declare their existing version

## ADDED Requirements

### Requirement: Existing-joint attachments retain dial operating history

An existing-joint attachment SHALL retain the original qualified bank id, rest/default binding, scalar coordinate count, retained-law behavior and snapshot state. The handle SHALL create no bank entry, identity wiring or additional compiled state. Explicit controls SHALL use the original joint node, axis, anchor and placement span. Equivalent ordinary-joint and frame-attached fixtures SHALL agree on admitted motion, stops, readouts, composed pose and replay under existing tolerances. Old fresh-freedom and rigid mate fixtures and non-mate documents SHALL retain their existing behavior and bytes.

#### Scenario: Seventeen dials remain seventeen original endpoints

- **WHEN** a Curta-shaped register fixture attaches eleven result dials and six counter dials through their existing site turn joints
- **THEN** all seventeen original child.turn ids remain banked once, guarded defaults are preserved, and register readings consume those same retained values

#### Scenario: Partial clearing retains its history

- **WHEN** a supported retained self-targeting dial law is stopped midway, resumed and replayed from a snapshot after frame attachment
- **THEN** its retained angle and readout match the original-joint witness and already-cleared dials do not move again

#### Scenario: Explicit controls select the original joint

- **WHEN** Turn/Button select a reused revolute mate or Slide/Button select a reused prismatic mate
- **THEN** the control publishes the original joint id and placement span, and the existing ancestry, domain, input-reachability and banking refusals remain effective

#### Scenario: Publication has no alias state

- **WHEN** an existing-joint attached fixture is exported
- **THEN** only its original qualified joint binding and ordinary frame-placement operations are published with no alias binding, new field or new document version

#### Scenario: Existing modes are unchanged

- **WHEN** old non-mate, fresh-freedom mate and rigid-mate fixtures are run and exported without the new form
- **THEN** existing binding/refusal behavior, program bank and document bytes are unchanged
