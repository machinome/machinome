# How AI is used in Machinome

Machinome is developed with AI coding agents. This file says which agents,
since when, how they work, and what the Git history records about their
work and what it does not, so that nobody reading this repository has to
guess.

## The line: 12 July 2026

Commit `81a330a`, dated 12 July 2026, is the first commit made with Claude
Code. From that commit on, every line of code and text committed to this
repository is written by an AI coding agent under the direction and review
of the maintainer, Luis Fagundes. He has written no code since. A commit
after the line is agent work whether or not it says so.

Before the line the code was written by hand by the maintainer. Parts of
some files in the first release (solid-node 0.0.1, 13 July 2023) were
generated by ChatGPT in a browser and pasted into the editor by hand; those
parts are not marked and cannot be told apart in the history.

## Two agents, and how the history marks them

Two agent tools have been used:

- **Claude Code** (Anthropic), from 12 July 2026. It appends a
  `Co-Authored-By: Claude …` trailer naming the model to every commit it
  makes.
- **Codex** (OpenAI), from the third week of July 2026; its first recorded
  use in the development workspace is dated 20 July 2026. It appends no
  trailer, and the maintainer did not enforce one.

So the trailers undercount agent work. As of 28 September 2026, 612 commits
follow the line: 387 carry a Claude trailer and the other 225 were made with
Codex. All 612 are agent work. Every commit is authored under the
maintainer's name because he makes them from his own account and answers
for them.

Nothing else in this repository is individually marked as machine-written.
The manual under `docs/`, the architecture synthesis and the ADRs, the
OpenSpec records and the notes under `workflow/` written since the line are
agent-written like the code, and reviewed the same way.

## How the agents work

The maintainer sets the interface, the top-level architecture and the
distribution of components. What gets built is decided empirically:
mechanical projects, existing open-source machines simulated by agents and
historical machines reconstructed by agents, produce findings; a finding
becomes a framework requirement; another agent implements it.

Every change runs through the discipline `README.rst` and `CONTRIBUTING.rst`
describe: proposed as an OpenSpec change, ratified by the maintainer before
implementation, implemented test-first with the failing test seen before the
fix, with rendered geometry inspected rather than trusted to a green suite,
and archived with its record. Architectural decisions are recorded as ADRs.
Agents never publish: tagging, pushing and uploading to PyPI are the
maintainer's own actions.

The maintainer's review is of design and behaviour. He ratifies each
proposal, reads the change records, runs and inspects the results, and
decides what integrates. He does not claim to have read every line the
agents wrote.

## Responsibility and licence

The agents are tools. The maintainer publishes their output under this
repository's licence, Apache-2.0, holds the copyright the `NOTICE` states,
and is responsible for it. No model is an author of Machinome.

## The other repositories

The same practice and the same line apply to the sibling repositories:
machinome-viewer, machinome-mechanics, molejo, machinome-studio,
machinome.org and the Foundry projects under
<https://github.com/machinome-foundry>. molejo, machinome-mechanics,
machinome.org and the Foundry projects were founded after the line and are
agent-written throughout; machinome-viewer's history before the line is
this repository's, from which it was split. Text a model wrote for
machinome.org is marked there file by file with the model and the date.
