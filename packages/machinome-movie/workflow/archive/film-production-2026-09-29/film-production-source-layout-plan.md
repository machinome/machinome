# Source/model presentation — narrow plan

Status: provisional working plan, 29 September 2026, for the commissioned film-production layout cycle. This is not an OpenSpec proposal, accepted format spelling or implemented behavior. It records the smallest source-only choice for root review; root/pilot retain authority over consequential presentation changes. No browser, speech or project source is changed by this note.

## Origin and boundary

Leonardo's `machinome-dark-source`, `machinome-dark-sequence` and `machinome-syntax-study` are disposable visual experiments, not supported Videomaker formats. Their inspected 28-second films put readable, literal, pinned Python on screen without a simultaneous machine, then, in the sequence and syntax study, cut machine → source → machine. The syntax study also lit three identifiers at measured narration onsets. They used private charcoal CSS, a separate experimental renderer, noncontiguous source excerpts and an initially visible prefix. Those details are evidence of one presentation need, not a mandate to promote the whole experiment or its dark aesthetic.

The supported 0.4 tool already has model-only shots when `code` is absent and a fixed code-left/model-right split when `code` is present, with pinned excerpts, typing, measured emphasis, chrome, progress and shot transitions. It cannot show a code-bearing shot as **source only** without leaving that supported renderer. That is the current gap. The current Leonardo sawmill/export is pinned to `28b43bce1b88446995f0ff231dd9075d1a839ab3`; `models/hydraulic_sawmill/model.py` line 415 is `water_drive.waterwheel.spin.drives(water_drive.crankshaft.spin)`. The syntax study's line 376 belongs to older `844c723…` and must not be copied as a current-source coordinate. The existing `demo-all-features` production selects current lines 413–415 and its source shot already uses line-415 emphasis.

## Smallest candidate contract for ratification

Add one optional **shot-level opt-in** in format 0.4, tentatively `layout: source-only`, accepted only when that shot has `code`. Its absence changes nothing: a shot without code stays model-only; a shot with code stays the present split. The source-only choice expands the existing source panel into the available picture region below the unchanged masthead/series and above the unchanged progress rule, using the episode's current background, foreground, accent, font and syntax colours. It shows no viewer canvas in the picture. The `code` snippet, typing cursor and measured identifier emphasis retain their current source, time and escaping rules; there is no separate scene format, theme engine, code-copy field or new source syntax. The precise field spelling and content rectangle belong in the later OpenSpec review, not in this note as a settled API.

One contiguous, export-pinned excerpt is enough to prove the requested model → source → model presentation on the **current** Leonardo source (for example the already selected 413–415 relationship). The old experiment's imports/class/drive collage would require noncontiguous ranges or an initial-prefix authoring feature; neither is necessary to establish source-only layout. Record those as evidenced possible follow-ons only if a later film actually needs that exact collage. Do not redesign the overall film dark or remove its chrome without the pilot's separate aesthetic decision. Preserving present styling here is a compatibility choice, not an assertion that the pilot approved a final look.

## Edge decisions for root review

- **No misleading model claims.** A source-only shot still carries the current required simulation/camera and real export pin; it does not invent a new model state. The page may keep a mounted viewer for continuity, but its canvas must not be visible in source-only captures. The existing canvas-fill assertion applies to visible model and split frames, not the deliberately source-only picture. Replace it there with source visibility, bounds, literal-text and overflow checks; do not report a hidden canvas as evidence of a visible model.
- **No covered target or misplaced picture.** `annotations` and `highlight` on a source-only shot should be refused at preflight because they name a model the audience cannot see. A source-only shot with a `pictures` cue should likewise be refused rather than inherit the current `code`-means-split stage geometry or silently cover its source. These are refusals for the new opt-in only; existing split/model picture rules stay intact. Ordinary overlays, external subtitles and film chrome retain their existing layers and timing, subject to their existing bounds/replay checks.
- **Independent incoming and outgoing pictures.** A shot's resolved frame should carry its own presentation choice, including the outgoing frame continued into the next shot's transition. Model → source and source → model joins use the existing fade/dissolve/wipe/slide semantics and global video time: the outgoing model continues at its existing end-rate; outgoing source holds its completed excerpt without a cursor; incoming source uses its own typing time. `pictureOnly` captures omit chrome and the final composition adds it once, unchanged. A hard cut needs no extra transition field. Neither side should inherit the other's layout by looking only at the active shot.
- **Source fit and cache identity.** The larger source panel must still refuse overflow on every posed frame, including outgoing continuation and a frame with measured emphasis; it must not shrink, scroll or clip text silently to pass. Existing line/source-revision and source-text equality checks remain. The chosen layout must enter actual `frameAt` requests and shot fingerprints, so changing it cannot reuse split-layout PNGs; no new global invalidation rule is justified merely by this option.

## Future proof before adoption

The later OpenSpec cycle should put refusals and visual distinctions red first, then demonstrate a short project-owned film at current source pin with visible animated model → source-only line 415 → visible animated model, plus one incoming and one outgoing join that exercise both layout directions. Compare old episodes with the option absent for exact unchanged frames; check source literal text, syntax/emphasis, panel fit and no model canvas in source-only pixels; prove model-only and split frames still fill their stage; verify chrome/progress, replay and exact transition pixels under the current browser/viewer. Intentionally long source, missing `code`, and source-only target/picture declarations must refuse by name. Root reviews the encoded film visually; tests do not declare the aesthetic approved. No new speech purchase or change to Leonardo's mechanical source/export is implied by this plan.

## Resolution — 29 September 2026

The `source-only-shots` change selected the narrow format-0.4 layout and is
implemented, synced and archived at
`openspec/changes/archive/2026-09-29-source-only-shots/`. Root verified the
real Leonardo films and exact cold/incremental output; see the campaign
report for the measured scope. The earlier experimental collage and dark
styling were not promoted. This plan remains the pre-spec record; the
archived change and current baseline own the accepted contract.
