## Context

`render()` currently hashes the entire resolved episode, all staged files, browser version, selected renderer modules, dimensions, FPS and captions into one `_build/frames/<hash>/` directory. It skips any nonempty numbered PNG and then encodes all numbered frames. Thus a local edit changes the whole cache identity; an interrupted directory has no trustworthy completion record. Leonardo's `demo-all-features` (nine shots, 46 seconds) exposed this during camera/title/timing corrections. The project-owned [short real-model baseline](/home/asa/devel/machinome/projects/Leonardo/videos/demo-incremental-rendering/evidence.md) measured 80 frames at 960 × 540 / 10 fps: 31.67 s cold, 1.70 s unchanged with 80 cache hits, and 32.11 s after a one-line title edit with 80 recaptures. Only output frames 21–42 changed bytes; the unchanged pixels were nevertheless recaptured. Those times bound the observed old behavior on that fixture, not a promised future speedup.

The browser's `pose(t)` builds the incoming frame from `frameAt(e,t)`, adds the film-wide progress `t / duration`, and may composite an outgoing frame from the prior shot inside a transition. `film.js` also mounts with the first frame and global style/series, and its repaint behavior must be proved independent of pose history. Captions are an external SRT, not burned into PNGs. Speech supplies measured onsets and source emphasis only where such cues are authored; the existing `speech` cache remains authoritative.

## Goals / Non-Goals

**Goals:** Reuse complete, integrity-verified shot frame sets when their actual pixels are unchanged; recapture only invalidated shot units; maintain global output-frame timing and fresh-render pixel equality; make capture/reuse and originating cache provenance visible in the output manifest. Preserve existing format and refusals.

**Non-Goals:** Per-frame or transition-prefix minimal invalidation, new author fields, parallel browser sessions, a general reproducibility audit, audio-cache redesign, speech generation, preview redesign, or publishing. A partial shot need not be resumed frame by frame.

## Decisions

### D1. A shot is the cache and invalidation unit

For each shot, enumerate **the actual global output indices** `n` for which `n/fps` lies in its half-open `[start,end)` interval. Include each `n`, exact `n/fps`, `frameAt(e,n/fps)` (with its outgoing transition payload), and `progress=(n/fps)/duration` in order in the shot fingerprint. The shot's start/end and the full index sequence are part of that fingerprint. Never build a local `k/fps` grid: a fractional shot boundary can begin between global frames. A shot with no output frame is still subject to the existing authoring/refusal rules, not silently fabricated.

The complete incoming shot is one unit, including all frames of its incoming transition—not a separately cached join prefix. Editing shot B invalidates B and the whole following shot C **if C's incoming transition uses B as outgoing**. Changing C's transition invalidates C, not B. An ordinary cut has no outgoing dependency. A timing change that shifts later global frame assignments invalidates the affected later shots through their index/time/request sequence. This is intentionally coarser than per-frame minimum but local enough for Leonardo's independent shots. The first shot's mount frame is a common dependency until history independence is proven across supported Viewer APIs; a change to that initial request may conservatively invalidate all shots.

Alternative: hash the whole episode (current behavior) or cache each frame independently. The former cannot serve the local-edit finding; the latter adds a more complex lookup and provenance model without evidence that it is needed.

### D2. Split common renderer inputs from reached shot media

The common fingerprint covers the viewer bundle and API, model manifest and its referenced assets, `film.html`/`film.js`, renderer/timeline/picture/word/code/easing/pixel logic and dependency lockfile, browser version, selected viewport/output dimensions and FPS, the effective font files and hashes known to the tested environment, style and effective `series ?? title` chrome, film duration, and the mounted initial frame plus actual visual mount options. It does **not** hash all of `/config.json`: its eager `pictureStills` name list and refusal text are not visual mount inputs, and including them would violate unused-media locality. A common change invalidates all shot units. In particular, changing total duration changes the progress rule on every output frame. Including the initial frame is a conservative boundary for this cycle (especially Viewer API 27), so a first-shot edit may invalidate all shots even when the later output requests look independent. Report that reason rather than claiming universally minimal invalidation; do not discard this dependency merely because API 28 tests pass.

The shot fingerprint includes its sequence of resolved frame requests and the hashes of only the stills and clip data **reached by those requests**, including any outgoing picture in a transition. For a still, use the staged source bytes. For a clip, use the source bytes, decoder/version/timestamp selection and the referenced extracted PNG bytes; do not include the extraction range or extraction-key hash of an unrelated shot merely because both use one clip. If another shot broadens the shared extraction range but this shot's selected bytes and timestamps remain identical, this shot remains eligible for reuse. These media dependencies and any relevant sizing data stay bound to the shot. Unused picture declarations, release metadata, evidence prose, narration text without a visual cue, and external SRT captions must not unnecessarily invalidate PNGs. They still update validation, audio/sidecars and the current render manifest. No cache hit may bypass `loadEpisode`/format/source/picture checks, `resolveWordTiming`, global-frame word-fit checks, or any existing refusal. Browser-only pose validations for a reused shot are inherited only from an attested capture with the identical effective dependencies.

For a spoken reveal or source emphasis, `frameAt` contains resolved visual timing and the fingerprint also binds the exact verified speech-take checksum. Changing that take or its alignment invalidates that shot (and any incoming shot using it as outgoing). An even reveal has no speech dependency. An audio-only narration change changes the final mix and output manifest, but not its PNG cache when the resolved visual requests remain identical. `check`, `preview`, and `render` never generate paid speech.

Alternative: retain `stage().hashes` wholesale in each key. This would make an unrelated still or clip edit invalidate every shot, defeating the empirical goal. A key based only on authored shot YAML would miss referenced presets, source text, measured onsets, media bytes and outgoing continuation.

### D3. Publish only a complete, verified shot generation

Capture a shot into its own unique generation directory under the new shot-cache namespace. After all expected global-index PNGs have been captured and checked for nonzero size and exact dimensions, write a generation index with schema version, common and shot fingerprints, shot ID, ordered frame indices/times, per-PNG SHA-256, capture provenance (tool/project heads and input hashes where available), and counts. Publish that index atomically **last**. A generation without its index, or with a missing, changed, malformed or wrong-dimension PNG, is not reusable; recapture the entire shot into a new generation. Do not accept a nonempty file alone. Completed earlier shots remain reusable after interruption, while an incomplete shot may be recaptured from its first frame. A later healthy generation is never overwritten by a failed attempt. Candidate selection must verify its index and all PNGs before reuse. Unique generation paths leave room for the later bounded-parallel investigation without implying concurrency in this change.

Do not migrate or read the legacy `_build/frames/<episode-hash>/` directories as shot caches: they have neither shot dependency attestations nor complete-frame integrity records. Leave those ignored files intact. Cache schema changes get a new namespace/version; a mismatch is a miss, never a guess.

### D4. Assemble and attest the current output

Encoding consumes each shot generation's global-index PNGs in exactly `0..count-1` order, with no holes or duplicated indices. The output MP4, thumbnail, SRT and description continue to use the current commands and semantics. Encode to a temporary output, probe its stream count/dimensions, hash it, and finish all required verification before replacing any good prior output. Publish the output and its new manifest only after that success; retain a prior good output as a recoverable generation through the narrow publication window. Because two path replacements are not one filesystem transaction, an interrupted publication may leave the previous manifest, but its recorded hash must then visibly fail against the current MP4 rather than falsely claim it. The manifest records, per shot, frame range, fingerprint, captured/reused count, generation path/index digest and original capture provenance; it also records current episode/production/project/tool provenance and the final MP4 hash. Reused frames are attributed to their originating generation, not represented as newly captured by the current commit. Report total captures/reuses, and ensure the manifest is only authoritative if its recorded output hash matches the present MP4.

Alternative: keep the old direct overwrite and only add counts. An interrupted encode could leave an old manifest beside a partial new MP4, making the provenance claim false.

### D5. Verify equivalence before claiming the optimization

Focused tests must first fail for local edit, neighbor transition, fractional starts/global grid, shared/global changes, audio/word alignment, media reachability, corrupt/missing/incomplete generations, and truthful report/output publication. A browser test compares **every PNG by checksum** from an incremental run and a forced-cold run, with source text, animated overlays, moving model and a join among the units; it also checks identical encoded frame sequence at the same FPS. If skipping cached frames changes browser pose history, fix deterministic posing/repaint in this cycle and repeat the equality proof; never lower the pixel threshold or claim that request equality alone proves raster equality.

The primary real Leonardo verification uses the approved `videos/demo-incremental-rendering` 8-second / 80-frame consumer derived from the real sawmill. Its four 20-frame shots are A `whole-machine`, B `feed-pawls`, C `water-drive` and D `return-to-whole`; C's incoming wipe shows B's continued outgoing picture. For the recorded B title edit, this design predicts **40 reused frames (A+D) and 40 recaptured frames (B+C)**, not 55/25 (which would split C into a transition prefix and unaffected suffix). Record actual counts, wall times and all-frame hash equality to a forced-cold render under the same inputs/environment. Focused real-source/text and fractional-grid cases cover those dependencies even if not all fit the short film. Preserve the validated original `demo-all-features` film and caches; do not claim performance benefit unless measured. Use existing ignored narration or silent evidence; no speech purchase or mechanical-source edit.

## Risks / Trade-offs

- [First-shot mount may influence later raster state] → Treat initial configuration as common, and compare cold vs incremental all-frame hashes across shot boundaries. Narrow only with evidence.
- [A whole incoming shot is invalidated for a brief transition] → Accept deliberate shot-level granularity; do not promise prefix-only reuse.
- [Global model, font, renderer or total-duration changes cause broad misses] → Preserve correctness and report the reason; these are genuinely common or conservatively treated as such.
- [Integrity hashing and extra on-disk generations add I/O/storage] → Measure against the empirical baseline; leave cache cleanup policy outside this cycle and do not delete historical caches.
- [A cached shot skips its browser pose checks during a subsequent render] → Re-run all preflight/word checks; bind runtime validation inputs to its generation fingerprint and reject any missing or damaged attestation.

## Migration Plan

Introduce the new namespace without deleting legacy caches. First new render is a cold capture; subsequent unchanged renders may reuse verified complete shots. A rollback to the prior tool ignores the new namespace and can use its legacy cache if still present. No episode migration is needed. The final output manifest identifies the cache schema so mixed-version records are never trusted.

## Open Questions

No author-facing decision is open. Empirical timings and the exact amount of savings await the separately measured Leonardo baseline and implementation evidence; they are completion evidence, not a license to weaken the equality or integrity contract.
