## Why

The Enigma I reconstruction (`projects/enigma-i`, root class `simulation/machine.py:Enigma`, a clocked machine whose drivers, states and instructions are declared on that class, 104-161) is operated in the browser through the panel the viewer builds from those declarations, and a reader cannot type on it. The pilot wants the model to carry its own **app**, a React application kept beside the model in the project's source (`simulation/app/index.tsx` with its components and stylesheet), which the viewer shows in place of that panel: an on-screen keyboard in the machine's layout, a box of case controls, a box of rotor controls with the three window numbers, and the picture filling the rest. The viewer's half is the companion change `show-a-models-own-app`. The framework's half is that a model can say it has an app, and that every document the framework publishes for the browser carries the app with it, bundled, beside the document: today nothing in the declarations, the build (`core/builder.py` `_write_viewer_snapshot`, 643-725) or the export (`core/export.py` `export_node`, 114-244) knows of one, and the build's sweep removes every file of the build directory the document does not name (`builder.py` 772-860).

## What Changes

- A node class may declare `app = 'app/index.tsx'`: a path to a TypeScript or JavaScript file, relative to the file that declares the class, as a movie's set or element names its `module` (`machinome-movie/machinome/movie/names.py` `module_path`, `declaring_class`, `module_directory`). The form is checked where it is written; `app` becomes a reserved class-body name, as `controls` is (`node/declarative.py` 1078-1144). Only the published root's declaration (its own or inherited) is read.
- A build (`machinome build`, `machinome develop`, and so the Studio's build directory) asks the viewer to **bundle** the root's app, through the seam of viewers and its new operation `bundle`, into the build directory beside `viewer.json`, and the document names the bundled script and stylesheet in a top-level `app` record. A content name means an unchanged app republishes nothing; the sweep keeps the files the document names and removes those it no longer does. A document whose root declares no app is byte-identical to today's, and no viewer is asked.
- **Refused by name, never substituted:** a declared file that does not exist, a file outside the project, a bundling viewer that is absent or cannot bundle, and an app the viewer refuses to bundle are each recorded in the document as the app's refusal, logged once, and the model is published as usual, so every page shows the model and names why its app is absent. The build's exit status reflects the model, as `machinome build`'s requirement says.
- `machinome develop` follows the app: the files the bundle read are watched beside the model's sources, and an edit to the app is republished by the builder that already holds the loaded model (bundled again, the document rewritten with the new record, the old files swept), without loading the model again or re-rendering any part; it falls back to the ordinary rebuild, saying so, only where another producer published meanwhile or nothing was published.
- The open development page is told when the document is **published**. Observed on the bench (`evidence/develop-reload-observation.md`): today a page receives `reload` when a builder exits, before the next one publishes, so it shows every edit one edit late; an app edit would too. `develop` now also calls the session's `reload()` each time `viewer.json` is replaced in the build directory, so the open page calls `manifestChanged()` on the published document and the viewer swaps the app in place with the picture standing. The same notification makes a Python edit appear when it is published; the respawn `reload` is kept.
- `machinome export` bundles the app into the export, beside `manifest.json`, `index.html` and `machinome-viewer.js`; an app that cannot be bundled fails the export before anything is written, naming why, because an export is what a reader receives. `machinome export --no-widget` of a model declaring an app is refused by name before anything is built: this change carries no app into a widget-less export.
- The seam of viewers gains the operation `bundle` (`OPERATIONS`, a Protocol, a default viewer, `web`); the web viewer offers it, the OpenSCAD viewer does not. The contract version stays 1: a viewer without the operation is refused by the seam's existing refusal, naming it.
- **A limit, not a contract:** in this change an app is bundled where the viewer's JavaScript dependencies are installed, which is a source checkout such as this workspace; elsewhere the viewer's refusal is the app's recorded refusal. Putting the toolchain into an installed copy is not in this change.

## Capabilities

### New Capabilities

- `model-app`: a model's root declares its app; a build publishes it beside the document and names it; refusals are recorded, not substituted; `develop` follows the app's files; an export carries it.

### Modified Capabilities

- `viewer-seam`: "The core declares the contract of viewers in one seam" and "Each viewer declares what it offers" are restated with the operation `bundle` (every baseline scenario kept, one added to each).
- `cli`: "Develop command" is restated so that every open page is told when a build replaces the published document (every baseline scenario kept, two added).
- `export`: "Export artifact contents" is restated so that an export of a model with an app carries its bundled files, an app that cannot be bundled fails the export, and a widget-less export of such a model is refused (every baseline scenario kept, three added).
- `user-documentation`: a requirement is added for the how-to that gives a model its app.

Review, 22 November 2026. The reviewer reviewed this change and its companion `show-a-models-own-app` adversarially under the pilot's standing delegation and accepted both with one blocking finding: `develop` following the app stopped at "the document is republished" and rested on an inferred reload timing, and an app edit restarted the builder, so the next one loaded the whole model again (for the Enigma, 3,347 parts) before it could bundle. Resolution: the timing was observed on the bench (the page is told before the build publishes and shows each edit one edit late), `develop` now tells the pages when the document is published, the watching builder republishes an app edit in place, and the requirement, the `cli` delta and the end-to-end test X2 prove that the open page shows the edited app with the picture standing (design Decision 5). The reviewer's rulings on the open questions are recorded in design "Rulings": a refused app does not fail `machinome build` (exit 0) and the export refuses it; a widget-less export of a model with an app is refused; the reserved name `app` stands; no type check of an app's sources. One question stays open for the pilot, the helper's licence (design "Open Questions"); it does not block. This is agent review under delegation, not a human review of the artifacts, and authorizes no integration, push or publication.
