## Goals / Non-Goals

**Goals:** Refuse non-finite or throwing final transform evaluation through the real mounted clocked handle; retain every standing placement and bank when refusal happens; retain successful event, binding and selective-update semantics; prove finite, visible retained geometry after failure and a subsequent valid move.

**Non-Goals:** No Enigma operational admission, complete-stroke claim, general solver, physical endpoint/stop, driver/State range enforcement, lamp or new control. ## Decisions

1. **Make transform preparation atomic at the tree boundary used by clocked admission.** Prepare all local matrices selected by the existing `Changed`/binding dependency rules into private request-local storage. Evaluate each selected operation once, with the current scope, operation order, degrees and binding resolution. Reject a thrown evaluation, a non-finite evaluated placement operand, or a non-finite resulting local matrix before copying any candidate matrix into a live group. A later failing sibling therefore cannot leak the prepared pose of an earlier one. Keep preparation private; the public machine hook/handle stays unchanged. A finite check only in `machine.ts` cannot see rendered operations; a per-node check alone cannot preserve earlier nodes; catch-and-repose can itself fail and repeats evaluation.

2. **Validate the transforms the scene will compose.** From candidate locals and retained unchanged locals, compose affected ancestor/descendant world transforms in the existing outer-operation order and refuse non-finite composition before publishing any transform. An unchanged child's local need not be re-evaluated when its parent's world placement changes. Do not normalize, clamp or substitute an identity matrix for invalid results. Do not introduce determinant tolerances or new malformed-document rules. Diagnostics identify the assembly path and operation index/type/expression for evaluated-operation failure, or the path for composition overflow; preserve useful original error details. This is a thrown pose refusal, not an admitted zero-travel stop.

3. **Use the existing commit hook and change tracking.** Successful preparation applies the already evaluated local matrices without evaluating them again, then takes the existing render path. The clocked executor still assigns its candidate bank only after the hook returns. Use this preparation before any live update for a clocked move, instruction or restore/reset pose. A transform refusal occurs before flexible shape reevaluation or other live pose mutation; retain existing flexible buffer reuse and avoid inventing a shape transaction in this cycle. The shared tree helper may protect other callers as a consequence, but running/posed semantics are regression coverage, not expanded public features. Keep instruction final-admission and intermediate drawing semantics as they are: this change does not evaluate new points along a path.

4. **Use source-owned, standard-published evidence.** Add a small authored clocked model and minimal rigid mesh fixture in viewer test fixtures, with an ancestor rotation reading the diagnostic expression and a rendered descendant, plus an earlier moving sibling. Use existing public primitives and a standard build/export to produce the retained document; preserve the source and regeneration/runtime/hash receipt. Include a state commit crossed before the invalid endpoint so bank and event atomicity are observable. The normal browser test consumes the retained document and official built bundle through existing support, public `machine()` and `partOnScreen`; it never requires the Enigma repository or native CAD. Native parity/regeneration is a separate development check against core 0.9.0 and need not add core imports to viewer runtime/tests. Do not edit core's solver or the pure bank-only conformance corpus to pretend it covers a rendered tree.

5. **Retain the evaluator's existing scope-keyed memoization; prove recovery instead of adding cache rollback.** Narrow review of `expressions.ts`, `bindings.ts`, `run/pose.ts`, `run/scope.ts` and `tree.ts` confirms that evaluating a candidate does mutate the page-shared `lastScope`, `passCounter`, and `nodeValue`/`nodeStamp` memo arrays. A computed NaN is cached for that pass; a throwing node is not stamped, although successfully computed children can be. These are value caches, not committed frame/bank state. `clockedScope` calls `nest(bank)` to allocate fresh nested driver maps and supplies the binding-root map through a generation-aware getter. `ensurePass` compares time, the entire nested driver map with `Object.is`, profile-table identity and binding roots; the standing scope differs from the refused candidate at the rejected input, so the next evaluated expression starts a new pass. A repeat of the identical invalid candidate can reuse its NaN and must refuse again. `withExpressions` unwinds nesting in `finally`, including on a throw. Lazy `WidgetTree.freeVars`, binding input closure, interned DAG nodes and generation-refreshed binding roots are structural/document caches, independent of candidate numeric values. Neither `tree.update` nor `clockedScope` stores a candidate as the viewer's standing frame scope; the machine hook returns before the bank is assigned, and drawings are started only after an admitted result. No evaluator-state snapshot/restore is needed on this mounted path. Keep request scopes immutable/fresh and retain these rules rather than introduce transactional global caches or clear shared caches on every refusal.

   Add a discriminating fixture path: an earlier sibling reads a shared binding of `press` plus an independent driver, while the later invalid node reads `press` only. After a refused `press` candidate has populated shared memo values, first re-evaluate the exact standing bank; separately repeat the refusal and, without changing `press` or rebuilding/resetting the mount, move only the independent driver. The sibling must use the original `press` binding and the new independent value; the failed node must remain at its standing finite pose without being re-evaluated for an unrelated change. Then a valid `press` request must recompute that node correctly. These tests distinguish whole-bank scoping from a cache incorrectly invalidated only for changed ids, and preserve selective evaluation. Exercise both a cached non-finite result and a thrown operation; do not mutate/reuse a scope object in place to manufacture a behavior the mounted path does not use.

## Risks / Trade-offs

- Preparation uses request-local matrix storage and composition work → retain selective expression evaluation, avoid persistent caches and scene cloning, and pin unaffected-branch evaluation counts. Discard storage on both success and refusal.
- A partial fix can preserve the bank while still moving scene objects → assert all sibling/ancestor matrices in unit tests and public visible part rectangles/pixels in browser acceptance, both immediately and after another render/query.
- Shared tree code reaches flexible/posed/running callers → prepare transforms before existing flexible updates, preserve buffers and normal consumers, run tree/flexible tests and existing clocked/running browser coverage. If implementation requires a new flexible transaction or a material change to evaluation semantics, return that evidence for scope review rather than silently expanding this cycle.
- Finite locals can overflow in world composition → validate the affected composed transforms using the same multiplication semantics; cover this distinct failure without adding geometric tolerances.
- Failure evidence can be accidentally replaced by a fresh build → retain the pinned Enigma packet read-only; run future caller revalidation only in its isolated diagnostic worktree, write new evidence beside it, and do not rebuild canonical main or overwrite the retained packet.
