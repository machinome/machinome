At load, two cyclic blocks have 31 and 16 laws. A per-tick bank audit found one unique IEEE input-state digest for the 31-law block across the 144 lever tick starts; the 16-law block had 138. In-memory timing instrumentation counted 147 calls of each across preparation plus gesture: about 7.4–7.6 CPU s for 31 laws, about 1.0 for 16. Of the 31-law block calls, 146/147 had every actual source `Motion.constant` (the initial crank-preparation call was nonconstant). All 147 output paths were constant with bit-identical start/end and positive-zero increments. Nine crossing records arose from the nonconstant preparation call; the constant-source calls wrote none. Neither block wrote a landing in this trace.

A deliberately narrow **unsafe-for-product** process-local memo, only for this 31-law block when every actual source path was constant and the exact finite source/held values matched via `Object.is`, saved a successful result only if it emitted no crossing/landing. It obtained 145 hits and reduced three instrumented gesture stages from 3.48/3.23/3.16 CPU s to 1.51/1.20/1.03 s, roughly 60–67% less per stage, with the same four full-bank digests, terminal statuses, admissions, final stop and clock. The normal nonconstant 18° crank was a negative control: zero hits and the same bank digest.

The experiment is not a production design: its cache was global, reused mutable `Motion` instances, and did not prove first-error order, custom/stateful-expression refusal, restore/new-Run isolation, signed-zero/terminal metadata, event history or arbitrary leave-and-return paths. The proposed implementation accepts only a successful pure numeric block with fully certified constant paths, exact dependency bits, no side effects and fresh scalar-described output paths, then must pass those separate adversarial gates. It cannot key merely on bank values or net deltas, and must be validated after the independently developed terminal-target viewer cycle integrates.
