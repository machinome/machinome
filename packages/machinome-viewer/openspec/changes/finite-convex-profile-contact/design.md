## Context

The Curta Type I reverser trial already expresses retained-phase-dependent axial stops with ordinary dynamic numeric Bounds: an angular contact flag selects absolute low/high axial planes on the held coordinate's side. It does **not** need a new span kind, constraint search, or rotating-contact certificate. The missing piece is a finite pointwise profile predicate. The project has .005 mm outward native covers with zero measured native remainder and an exploratory union of separately projected mesh triangles. Those records do not yet prove complete installed-print or axial coverage, so project adoption remains outside this viewer cycle. A 591-piece pinion against a 1,072-piece drum would spell 633,552 pair tests as scalar formulas; a capped 256-pair experiment already consumed 49,833 unique DAG nodes. The viewer currently reclaims expression nodes at 125,000 and executes numeric bounds through a shared expression DAG and a determined-bound `ExpressionPath` fast path.

The viewer is an independent AGPL package, now at API 25 and reading documents 1–12. The framework separately owns the public Python constructor, producer validation, table deduplication and version-13 serialization. This cycle only consumes the frozen producer wire and runs the same numeric predicate in the browser.

## Goals / Non-Goals

**Goals:** Read a finite producer-declared table; evaluate `profileOverlap` as numeric 0/1 inside existing running Bound expressions, including binding aliases; preserve numeric Bound admission, stop, restore and multi-mount identity. Reject malformed profiles, calls and nonfinite placements without rendering or committing a tick. Demonstrate useful throughput and paired producer/viewer outcomes on the actual Curta-sized table, including bounded reuse of measured repeated contact work within one integration attempt.

**Non-Goals:** No CAD or mesh Boolean in the viewer, generated all-pairs expression graph, arbitrary polygon decomposition, collision volume, clearance epsilon, altered 64-sample/bisection search, swept rotating-contact certificate, new public mount API, change to document versions 1–12, or claim that the current Curta cover is mechanically complete.

## Decisions

1. **Wire and gate.** Version 13 adds `program.profiles`, an ordered array of `{points:[[x,y],...], polygons:[[vertexIndex,...],...]}`. A call has exactly eight scalar operands: `profileOverlap(leftIndex,rightIndex,leftAngleDeg,leftTx,leftTy,rightAngleDeg,rightTx,rightTy)`. The first two must be literal nonnegative integer AST leaves naming existing table entries; they are not dynamic expressions. Only a running Bound (or binding transitively read by one) may use the call. Producer hashes canonical table content into Program identity and publishes version 13 only when this feature is used. Viewer support raises its advertised API capability to 26. Older documents keep their original code path; an older viewer refuses version 13 rather than silently ignoring contact.
2. **Load-time validation.** The viewer validates table shape, finite binary coordinates, polygon index ranges, at least three geometrically distinct loop vertices, nonzero exact signed area, CCW convex cyclic order, nonzero edges and simplicity before a run starts. Exact-binary orientation of the supplied doubles permits collinear consecutive edges, but an adjacent backtrack or nonadjacent edge crossing/touch is not a simple convex loop. Check exact-binary segment intersections, including a pentagram whose local turns all appear positive; no floating epsilon, strict-turn shortcut, or latitude to reject a valid producer-authored loop because the viewer did not implement certification. Refuse malformed table, out-of-range/nonliteral call indices, wrong arity, a reserved-name collision, and calls outside supported Bound reachability. Retain the producer's polygon order and coordinates; do not infer a hull, weld nearby points, mirror sectors or fill gaps. At evaluation, any nonfinite placement input or transformed coordinate/projection is a named refusal, not a clearance result.
3. **One pointwise predicate.** Place each referenced profile in this paired binary64 order: `theta = angle * 0.017453292519943295` (constant `0x1.1df46a2529d39p-6`, one multiplication, no explicit reduction); `c = cos(theta)`, `s = sin(theta)`; for every vertex `rx = (c*x - s*y) + tx`, `ry = (s*x + c*y) + ty`. Check the angle, theta, trig results, each product/sum and transformed coordinate for finiteness. Initialize each world AABB minimum/maximum from its first transformed vertex and update in serialized vertex order with strict `<`/`>` only, retaining the first signed-zero tie. Validate every transformed edge axis (`nx = u.y - v.y`, `ny = v.x - u.x`) for finiteness and both-zero collapse before pair AABB rejection; a distant other profile cannot mask an invalid placement. For polygon pairs in serialized order, reject disjoint world AABBs first, then test both polygons' ordered prevalidated edge-normal axes with ordered projections. Compute each projection as `px = x*nx`, `py = y*ny`, `p = px+py`, check every intermediate for finiteness, and update extrema with first/strict comparison. Separation is **strict** `<`; a shared projection endpoint counts as contact. Return numeric `+1.0` on the first pair with no separating axis and `+0.0` only after every pair is separated. This is a bounded finite early-exit computation, not a penetration depth or continuous path certificate. The shared red corpus includes touch, strict gap, signed-zero ties, reversed pair order, near tangency, huge finite angles, transformed overflow/collapse despite disjoint AABBs, and actual Curta states; no arbitrary tolerance forces parity.
4. **Program-scoped expression evaluation.** The table and callable belong to the loaded program, not a module-global mutable registry. Extend expression scope/pass equality with the program's profile-context identity so identical AST and bank values from two mounted documents cannot reuse the wrong cached result. Reserve `profileOverlap` as a function token after existing binding/driver collision validation; aliases of the call inherit the same context. The determined-bound `ExpressionPath` path must either evaluate the same scoped primitive or conservatively fall back to ordinary `evaluateExpression` **before** any eager partial work, preserving first-error order and existing arithmetic around the call. Ordinary laws, other bounds and legacy documents do not acquire a new scope cost when no table is present.
5. **No solver change.** The predicate's 0/1 value is composed by the authored expression into an absolute numeric Bound limit, as the Curta local trial does. `Constraint` still reads a numeric bound; the existing quiet-read shortcut, prescribed samples, bisection, admission attribution, committed-bound check and snapshot identity remain. Tests must not claim first contact between samples or a continuous collision certificate. A missing profile capability or unsupported expression fails at load; a runtime numeric failure refuses the tick atomically.
6. **Recorded baseline versus source capability.** The 0.7.0 record remains API 25/documents 1–12; current shop state does not establish that these repository bytes have been pushed or uploaded. The current manual home uses `|viewer-api|` and `|document-versions|` substitutions read directly from widget source inside a sentence about that 0.7.0 record; increasing the source declaration without changing this wording would falsely attribute API 26 to that baseline. Keep baseline facts and current-source `describe` facts distinct in the owning compatibility/status surface and home note; test both against their respective records, without adding an unverified publication claim. Document the new source capability in an Unreleased API 26 changelog section and the relevant running/compatibility reference, without a new host operation or a project/workspace story in reader pages. The CLI `describe` example continues to match the actual source declaration.
7. **Measured private integration cache.** The installed Curta local trial calls the profile predicate 1,560 times in one tick, but the paired lower/upper Bounds contain only 780 distinct exact pair keys; 3,120 full-profile placements contain only 136 distinct profile/placement keys. A Python process-local diagnostic reduced one tick from 13.72 to 8.34 CPU seconds with the ordered contact and full-bank hashes unchanged. Independently, the pinned viewer document `bfba823b...` produced the same 1,560/780 pair and 3,120/136 placement counts, completed an 18° tick with a 214-coordinate bank, and consumed 2.914 CPU seconds on reserved CPU 13 before caching. Use one private cache for a single Run integration attempt, never a module-global retained table: a 1,024-entry contact-result LRU and 256-entry placed-profile LRU. Key each by the immutable loaded profile identity and the exact finite IEEE-754 bits of every numeric angle/translation, distinguishing both signed zeros. Only primitive finite numeric operands are eligible; if **either** placement key is uncertain/custom/coercing or nonfinite, bypass both caches for the whole call and use the original path. Evaluate expression operands in their original order before lookup. On a miss, validate both complete placements and evaluate the pair in the original order; publish successful pair and any newly prepared placements transactionally only after the whole predicate succeeds. Errors are never cached and a failing right placement cannot publish the successful left preparation. Cache hits may skip only the proven deterministic profile transform/SAT work, never an operand evaluation or required guard. The cache expires after that integration attempt, including failures; separate runs, mounts, ticks and restored attempts cannot share it. Direct numeric calls outside an integration attempt remain uncached. Caps limit retention, not valid input size or admission; an eviction merely recomputes.

Alternatives rejected: a specialized typed span would change the solver without an originating need; putting every polygon-pair SAT term in GraphValue is measured infeasible; a global profile registry risks cross-mount cache contamination; a faceted/CAD Boolean or clearance epsilon would answer a different question.

## Risks / Trade-offs

- **Near-tangent numeric disagreement** → Freeze arithmetic order and conformance fixtures; treat unresolved cross-runtime disagreement as a failed gate, not a silent tolerance or clearance decision. Inclusive touch is a predicate rule, not a promise of universally bit-identical transcendental functions.
- **Malformed nonconvex data can hide contact** → Reject invalid indices, zero edges, adjacent backtracking, self-crossing loops and other non-simple geometry before mount with exact-binary orientation/segment tests; never repair a profile in the viewer.
- **Large table and repeated SAT cost** → Keep data outside the expression DAG, precompute per-profile immutable local facts only within a bounded loaded-program lifetime, use pair AABB rejection and first-contact exit, then add the above private bounded integration cache only after counted viewer evidence. No unbounded global or cross-tick cache. A cached placed Curta profile contains many vertices, so the placement cap is 256 rather than a generic large pool.
- **Alias/path-cache interaction** → Test direct and bound-binding calls, fallback error order, stale expression-store generation, simultaneous distinct documents and snapshot restore.
- **Project proof incomplete** → A green paired corpus, bounded current Curta local-Bound trial and source-profile witnesses can establish the viewer capability without asserting complete Curta production adoption. Installed-print, axial-slab and full-motion proof remain independent project gates.

## Migration Plan

No migration for versions 1–12. Pair a framework v13 producer export with a viewer advertising API 26; an older viewer refuses that document. Build and smoke an isolated viewer bundle and compare it with the producer's pinned corpus before any local integration. Reverting this cycle returns the viewer to API 25/documents 1–12; no existing document or host API is rewritten.

## Open Questions

The producer must pin an exact v13 fixture and numeric parity corpus using the operation order above before implementation; a discrepancy in near-touch arithmetic returns the paired plans for revision rather than being accepted under a blanket epsilon.
