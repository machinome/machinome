# OperatingCurta clean rebind experiment — rejected

The named higher-counter OperatingCurta export (`manifest.json` SHA256 `f58da4f21142d452bd6de58adc901fafa131d81fcaaf301df7fc767f2269dc67`, program identity `4127d33c87f1501a024ee5c7391d1897ce3af65309b946c811d4244c7fd68da2`) was run without WebGL at the viewer default `dt=1/240`: selector 1 set immediately, then a declared 360° crank request over 2 seconds. These measurements cover only the first 48 of 480 ticks and 36° of admitted travel, not a completed turn.

Instrumentation over the first 12 ticks found 618,561 `PathValue.bind` calls, of which 542,535 (87.7%) resolved no new expression nodes. Those binds checked 1,062,064 input leaves. A V8 CPU profile of a 48-tick baseline attributed about 3.49 seconds of self time to `PathValue.bind` and 2.46 seconds to GC. This was concrete evidence to try removing clean-bind allocations.

The red-first test trapped a newly constructed dirty `Set` during a distinct-object clean bind; baseline failed exactly there, and both candidate variants passed. Existing presence, `Object.is`, signed-zero, NaN, sampled-point and full-expression tests passed; a dedicated later-throwing getter test preserved observed input order. The first candidate compared leaf presence/value as primitives and allocated replacement snapshots and a dirty set only on a difference. A second, smaller candidate retained `inputAt` but allocated the dirty set lazily. Both preserved the first-48 bank SHA256 `790e76a9aaae36bf703b6aa74f8722771fa87e1379ab6375f033153729a09bb6`, 213 coordinates, admitted 36°, and expression resolution count 54,516,653.

Neither passed the performance gate on reserved CPU 15. Primitive/lazy-set candidate trials took 24.662 and 21.406 process-CPU seconds; lazy-set-only took 24.003 seconds. Adjacent unchanged baseline runs took 19.149 and 20.024 seconds (an earlier baseline took 20.940). Host load and JIT/GC make individual samples variable, but no measured pair showed a material gain; several showed a regression. The cause was not established, so no V8-specific story is inferred. Both experimental runtime edits and their temporary tests were removed. The OpenSpec planning proposal remains on this isolated branch as a rejected experiment, not an implemented capability, and must not be synced or archived as accepted.
